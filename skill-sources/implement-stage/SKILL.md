description: Полностью реализовать один заранее ограниченный этап дорожной карты с делегированием специалистам, тестами, проверкой и обновлением статуса.
---

1. Прочитай `AGENTS.md`, `docs/AI_STATUS.md`, `docs/AI_PLAN.md`, `docs/ARCHITECTURE.md` и `specs/README.md`.
2. Найди относящуюся к этапу SPEC и её критерии приёмки. Для новой существенной `STANDARD` или `COMPLEX` функциональности не начинай реализацию без SPEC.
3. Если ограниченного плана нет, сначала запусти процесс планирования.
4. Назначь непересекающиеся области файлов минимально необходимому числу агентов с правом записи.
5. До параллельной реализации явно зафиксируй контракты базы данных, API и интерфейсов.
6. Сначала запусти самые узкие релевантные тесты, затем необходимые для этапа интеграционные тесты.
7. Проверь связь SPEC → критерии приёмки → тесты → реализация.
8. Запусти `reviewer`; добавляй `security_reviewer` или `performance_engineer` только тогда, когда изменение этого требует.
9. Исправь замечания с высокой достоверностью; допускается не более двух циклов проверки.
10. Перед `DONE` выполни Completion Documentation Synchronization Gate из global Skill `dev-karkas` (`~/.agents/skills/dev-karkas/references/STATUS_WORKFLOW.md`): всегда проверь `README.md`, `docs/AI_PLAN.md`, `docs/AI_STATUS.md`, `docs/ROADMAP.md`, stage tracker и другие state-bearing документы; обнови изменившиеся факты и не создавай churn в точных документах.
11. После разрешённого merge повтори gate по target branch и только затем фиксируй merge-level status и следующий этап.
12. Не выполняй push, развёртывание или публикацию, если пользователь явно не запросил это внешнее действие.
