# Project files policy

Используй этот документ как карту назначения, а не как обязательное дерево.

| Artifact | Назначение | Создавать когда |
|---|---|---|
| `AGENTS.md` | project-specific инструкции агентам | почти всегда для agent-driven проекта |
| `README.md` | вход для человека/разработчика | почти всегда |
| `SPEC.md` | требования продукта/системы | когда требования сложнее README |
| `DESIGN.md` | каноническая архитектура | когда есть несколько модулей/слоёв/существенные trade-offs |
| `SECURITY.md` | security baseline | есть сеть, пользователи, данные, upload, auth или публичный API |
| `ROADMAP.md` | направления и крупные этапы | roadmap реально используется |
| `AI_PLAN.md` | ближайший исполнимый план | длительная agent-driven разработка |
| `AI_STATUS.md` | подтверждённое текущее состояние | длительная agent-driven разработка |
| `decisions.md` / ADR | журнал важных решений | решения имеют долгий хвост |
| `PROMPTS/` | implementation prompts/stages | разработка ведётся этапами |
| `LEARNING.md` | повторно полезные выводы | есть диагностические/инженерные знания |
| `DEV_LOG.md` | краткий журнал существенных работ | нужен trace, отличный от git history |
| `COMMERCIAL_PRODUCT.md` | коммерческие правила | продукт коммерческий |

## Именование и канон

1. Не переименовывай существующий канонический файл только ради совпадения с таблицей.
2. Если два документа делают одно и то же, выбери один канон и постепенно устрани дублирование без потери содержимого.
3. Ссылки между документами предпочтительнее копипаста.
4. Не создавай пустые placeholder-файлы без ближайшего полезного содержания.
5. Не генерируй `SNAPSHOT.md`, если `AI_STATUS.md` уже выполняет эту роль.

## PROMPTS

Рекомендуемая форма:

```text
PROMPTS/
├── 001-<stage>.md
├── 002-<stage>.md
└── BACKLOG/
    ├── <feature>.md
    └── <architecture-change>.md
```

Нумерация отражает утверждённую последовательность. Сырые идеи остаются в backlog до refinement/approval.
