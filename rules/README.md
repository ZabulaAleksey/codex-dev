# Маршрутизация инженерных правил

Этот каталог содержит выборочно подключаемые правила AI Dev Team. Его нельзя целиком загружать в контекст каждой задачи.

## Шесть измерений маршрутизации

Перед существенной программной задачей определи:

1. сложность: `SIMPLE`, `STANDARD` или `COMPLEX`;
2. режим разработки: prototype или production;
3. текущий этап SDLC;
4. технический домен;
5. используемый стек;
6. соответствующую спецификацию в `specs/`.

После классификации прочитай только:

- одно правило режима из `rules/modes/`;
- одно или несколько правил текущего этапа из `rules/sdlc/`;
- только затрагиваемые домены из `rules/domains/`;
- только фактически используемые технологии из `rules/stacks/`;
- индекс `specs/README.md` и непосредственно относящиеся к задаче SPEC.

Не загружай все правила доменов, стеков или этапов одновременно.

## Каскад контекста

Правила уточняются сверху вниз:

```text
Глобальные принципы
    ↓
Режим разработки
    ↓
Этап SDLC
    ↓
Домен
    ↓
Технологический стек
    ↓
Правила проекта
    ↓
Feature SPEC
    ↓
Текущая задача пользователя
```

Более конкретное правило имеет приоритет над общим. Прямая инструкция пользователя остаётся приоритетной, если не нарушает ограничения безопасности.

## Минимальная активация

- `SIMPLE`: не активируй полный SDLC; проверь существующую SPEC только при изменении наблюдаемого поведения.
- `STANDARD`: используй `rules/modes/standard.md`, правило текущего этапа и соответствующую SPEC.
- `COMPLEX`: используй `rules/modes/strict.md`, SDD, необходимые review-этапы и правила затронутых доменов.
- Эксперимент: используй `rules/modes/prototype.md` и явно отделяй временные решения от production.

## Дополнительные прикладные стандарты

- Для учебных проектов с итоговыми Word/PDF-документами загружай `rules/word-pdf-academic.md`.
- Не загружай этот стандарт для задач, не связанных с учебными документами, расчетами или их оформлением.
- Локальные индексы `rules/sdlc/README.md`, `rules/domains/README.md` и `rules/stacks/README.md` помогают выбрать минимальный набор фрагментов без загрузки их содержимого целиком.

## Сквозные политики

Некоторые правила не относятся только к одному стеку или SDLC-этапу.

- Если операция допускает retry, альтернативный tool/model/backend/data source,
  частичный результат или другой degraded mode, загрузи
  `rules/fallback-policy.md`.
- Если задача работает с Node.js, Corepack, npm, pnpm или Yarn,
  загрузи `rules/node-package-management.md`.
- Если задача выбирает dependency manager, меняет lockfile, восстанавливает
  dependencies либо проверяет cache/build drift, загрузи
  `rules/dependency-management.md`.
- Сквозная policy подключается только при наличии соответствующего риска;
  не загружай её автоматически для каждой простой задачи.
