# Этап тестирования

- Тестируй наблюдаемое поведение и идентификаторы требований SPEC.
- Для bugfix сначала создай или найди воспроизводящий падающий тест.
- Проверяй основной поток, ошибки, границы и регрессии.
- Выбирай минимальный достаточный уровень: unit, integration, contract или E2E.
- Не переписывай production-код только ради прохождения некорректного теста.
- Для непокрытого требования явно укажи способ ручной проверки и причину отсутствия автоматизации.
- Для закрытия stage выполни concrete end-to-end consumer path из Stage contract; отсутствующий
  обязательный backend означает `BLOCKED_BY_BACKEND`, а mocks/stubs подтверждают только scaffold.
