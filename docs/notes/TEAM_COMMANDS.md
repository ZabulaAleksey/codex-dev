# Команды и формулировки для AI-команды

## Посмотреть состояние проекта

```text
$resume-project
```

или:

```text
Прочитай AI_STATUS, ROADMAP и specs/README.md. Скажи, на каком мы этапе, какая SPEC относится к следующему шагу и что минимально нужно сделать. Ничего не меняй.
```

## Спланировать этап

```text
$plan-stage
Спланируй этап 4. Найди или подготовь соответствующую SPEC, свяжи план с её требованиями и критериями приёмки. Используй architect + explorer и профильного специалиста. Ничего не реализуй.
```

## Реализовать этап

```text
$implement-stage
Реализуй текущий AI_PLAN по соответствующей SPEC. Параллельные агенты с правом записи должны владеть непересекающимися файлами. После тестов проверь критерии приёмки и вызови reviewer.
```

## Явно вызвать конкретных субагентов

```text
Параллельно запусти architect и explorer. Дождись обоих. Затем передай backend/** агенту backend_engineer, а frontend/** агенту frontend_engineer. После их завершения запусти test_engineer и reviewer.
```

## Исследовать технологию

```text
Используй docs_researcher. Проверь актуальную официальную документацию <технология>, совместимость с нашим стеком и предложи минимальный эксперимент. Не добавляй зависимость.
```

## Проверить изменение

```text
$review-change
```

Проверка должна отдельно показать соответствие SPEC, тестов и реализации.

## Объяснить сделанное

```text
$explain-change
```

## Субагенты в интерфейсе Codex

- `/agent` — посмотреть потоки субагентов и переключаться между ними.
- `/skills` или `$skill-name` — выбрать skill.
- `/hooks` — проверить определения hooks и разрешить доверенные.
- `/mcp` — посмотреть MCP в интерактивном клиенте; `codex mcp list` — из shell.
