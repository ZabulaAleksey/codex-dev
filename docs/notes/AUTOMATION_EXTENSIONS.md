# Опциональные расширения автоматизации

Этот документ описывает направления расширения, а не активные возможности. Наличие файла в библиотеке не означает, что agent, hook, MCP или Skill установлен в Codex.

## Когда расширение оправдано

- маршрутизатор правил выбирает только относящиеся к задаче фрагменты из `rules/`;
- curator архивирует устаревший контекст и сохраняет `AI_STATUS` компактным;
- architecture check обнаруживает расхождение кода с `ARCHITECTURE.md` и предлагает ADR для намеренного изменения;
- benchmark check хранит воспроизводимую базовую линию для performance- или hardware-решений;
- design drift check сравнивает UI с `DESIGN.md`, tokens, components и эталонными screenshots;
- handoff передаёт цель, requirement IDs, владение файлами, принятые решения, выполненные тесты и блокеры;
- workload-анализ классифицирует узкое место как CPU, memory, I/O, latency, realtime, distributed или ML до выбора ускоряющей технологии.

## Ограничения

1. Сначала проведи аудит по `docs/CONTEXT_COMPATIBILITY.md`.
2. Предпочитай существующие agents, Skills, hooks и MCP.
3. Добавляй автоматизацию только при измеримом пробеле и с минимальными разрешениями.
4. Для эксперимента зафиксируй цель, критерии успеха, fallback, тесты и, при необходимости, feature flag, benchmark, ADR и rollback.
